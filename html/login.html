Mirror a site behind a login or a CAPTCHA

Some sites show their pages only after you log in, or only after you pass a check such as a CAPTCHA. HTTrack cannot fill in a login form and cannot solve a CAPTCHA. But it can use the session of a browser where you already logged in.

When to use this method

Use it when one of these is true:

  • The site has a login form, a single sign-on page (SSO), or a second step such as a code from your phone (2FA).
  • The site shows a CAPTCHA, or a "checking your browser" page, before the content.
  • The mirror contains the login page instead of the pages that you see in your browser.

Some sites ask for a user name and a password in a small browser window (HTTP Basic authentication). For these sites, you do not need this method. Put the user name and the password in the address, for example https://user:password@example.com/. The FAQ tells more.

How it works

When you log in, the site gives your browser a cookie. The browser sends this cookie with each request, so the site knows that you are logged in. You copy the cookies from your browser into a file, and HTTrack sends the same cookies.

You also give HTTrack the User-Agent of your browser. The User-Agent is the text that tells the site which browser it talks to. Some sites accept a cookie only from the browser that received it.

Step 1: export the cookies

  1. Log in to the site with your usual browser. If there is a CAPTCHA, solve it. Then open a page that you want to copy, to make sure that you are logged in.
  2. Save the cookies of this site to a file named cookies.txt, in the Netscape format. Two tools can do this:
    • A browser extension. The extension "Get cookies.txt LOCALLY" is open source, and it is available for Firefox and Chrome. It writes the file on your computer and sends nothing to other computers. Export only the cookies of the site that you want to copy.
    • curl. For a simple login form, curl can log in and save the cookies with its -c option: 
      curl -c cookies.txt -d 'user=me&password=secret' https://example.com/login
      Change the field names and the address to match the form. This does not work if the login has a CAPTCHA or a second step.

Be careful with cookie extensions. An extension that reads your cookies has the keys to all your accounts. An older extension with a similar name, "Get cookies.txt" (without "LOCALLY"), sent the data of its users to a remote server. It was removed from the Chrome Web Store in 2023. Do not install it.

A cookie file is as good as your password. A person who has the file can use your session. Do not share it, and delete it when the copy is done. When a crawl ends, HTTrack writes the cookies that it holds back to the file that you gave with --cookies-file, and keeps the old file as cookies.txt.bak. Delete both files.

Most session cookies are marked "HttpOnly". In a cookies.txt file, the lines of these cookies start with #HttpOnly_. HTTrack versions newer than 3.50.5 read these lines. Older versions think that they are comments and ignore them, so the login does not work. With an older version, remove #HttpOnly_ from the start of these lines.

HTTrack keeps a cookie only if its name and its value together are 4096 bytes or less. It ignores a longer cookie and writes a warning in its log.

Step 2: find the User-Agent of your browser

Use the same browser that you logged in with:

  • Firefox: type about:support in the address bar. Copy the "User Agent" line in the "Application Basics" section.
  • Chrome or Edge: type chrome://version (or edge://version) in the address bar. Copy the "User agent" line.
  • All browsers: press F12 to open the developer tools, and open the "Console" tab. Type navigator.userAgent and press Enter.

Copy the full text, with no change. It starts with Mozilla/5.0.

Step 3: run HTTrack

On the command line, give the cookie file with --cookies-file (-%K) and the User-Agent with --user-agent (-F):

httrack https://example.com/members/ -O mysite \
    --cookies-file cookies.txt \
    --user-agent "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/141.0.0.0 Safari/537.36" \
    --sockets=2 \
    "-*logout*" "-*signout*" "-*sign-out*"
  • Use the User-Agent that you copied in step 2, not the one in this example.
  • --sockets=2 (-c2) opens only two connections at a time. Many fast requests from one logged-in user look like abuse, and the site can then end your session.
  • The filters "-*logout*", "-*signout*" and "-*sign-out*" stop HTTrack from following the logout link. A visit to that link ends your session. Look at the address of the logout link on your site, and add a filter for it if its name is different. The filter syntax page tells more.
  • When the User-Agent is a browser, recent versions also send the other headers that this browser sends (--browser-headers, -%Q). This is on by default.

If you put the file in the project folder with the name cookies.txt, HTTrack also reads it without --cookies-file.

WinHTTrack and WebHTTrack

Click "Set options", then:

  • On the "Spider" tab, type the path of the file in "Load cookies from file". Keep "Accept cookies" selected.
  • On the "Browser ID" tab, paste the User-Agent in "Identity".
  • On the "Flow Control" tab, set "N# connections" to 2.
  • On the "Scan Rules" tab, add -*logout* and the other logout filters.

A built-in "log in with a browser" step is planned for WinHTTrack and for the Android app.

Limits

  • Cookies expire. A session can end after some minutes or some days. If the mirror starts to contain login pages again, log in again, export the cookies again, and continue the mirror.
  • Bot protection can still refuse HTTrack. Services such as Cloudflare give a "clearance" cookie after a check. This cookie is tied to your IP address, to your browser and to your device. HTTrack connects in a different way from a browser, and these services can see the difference. So a site with strict protection can refuse HTTrack, even with the correct cookies and User-Agent. When HTTrack sees such a refusal, it writes a "Bot protection challenge" warning in its log.
  • HTTrack does not solve CAPTCHAs. It does not use CAPTCHA-solving services.
  • Respect the terms of the site. A login does not give you the right to copy everything. Read the terms of use of the site, and read Using HTTrack responsibly.
