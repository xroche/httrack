# AGENTS.md: working in the HTTrack tree

Policy and PR etiquette live in [CONTRIBUTING.md](CONTRIBUTING.md).

## Build & test
- Fresh clone first: `git submodule update --init src/coucal`
- Run `./bootstrap` (it runs `autoreconf` and needs autoconf, automake, libtool), then `bash configure && make -j"$(nproc)" && make check -j16`, or `sh build.sh` for all but the check.
- Always pass `-j` to `make check`. Each crawl test binds its own ephemeral-port server, so `-j` never contends. Tests mostly sleep, so the width is not a core count. On 4 cores `-j8` takes 245s and `-j16` 161s, so `CHECK_JOBS` is 16 in `ci.yml`, `tier2.yml` and `sanitizer.yml`. macOS copes because the test server raises its listen backlog (`request_queue_size`) above Python's default of 5, which dropped connections under a parallel `-c16` bigcrawl.
- `configure` globs `TESTS` from `tests/[0-9]*_*.test`, so a new test needs no registration. An existing build dir keeps its old list, so reconfigure or `231_test-names.test` goes red. It also compares the glob against `git ls-files`, so it fails on a test you forgot to `git add`. `tests/check-test-names.sh` (a CI lint) rejects a name outside the pattern, which never runs.
- **A test that skips on Windows needs registering twice.** Add a new `skip_on_windows` test to BOTH the msys and the wsl2 list in `tests/ci-windows-suite.sh`, with its reason in the comment above. Otherwise `libhttrack (x64, Release)` reds with "skip set changed from expected". The check keeps an all-skipped suite from reporting green having tested nothing.
- **`make check` puts a RELATIVE `src/` on `PATH`.** A test that runs `httrack` by name after a `cd` finds the INSTALLED one. That fails as if your change were wrong, so resolve the binary to an absolute path first. A hand-run `.test` gets no `src/` at all, so set `PATH="<bld>/src:$PATH"` or `/usr/bin/httrack` shadows your build.
- **Tier-2 holds the slow legs** (configure variants, macOS bundle, emulated s390x, distro canaries) in `tier2.yml`. It runs weekly on master, so run `gh workflow run tier2.yml --ref <branch>` before a release. An absorbed workflow keeps `workflow_call` and `workflow_dispatch` and has no schedule of its own, so dropping its `uses:` from `tier2.yml` stops it. The outside-world canaries (`appstream-network`, `mptcp-network`, `downstream-drift`, `httraqt-upstream`, `psl-drift`) keep their own cron and stay out of tier-2, because they must fire when no branch moved.
- `distcheck` is a required context and builds from the dist tarball, which has no `.github/`. A test reading a file there skips when the directory is missing, and fails only when the file alone is missing. Tests 226, 278, 399 and 432 carry the pattern.
- Give new `.test` scripts `set -e`, because several `local-crawl.sh` calls without it report PASS on any non-last failure.
- After a `( ... )` statement, write `subshell_ok $?` on the next line. macOS bash 3.2 ignores a failing subshell under `set -e`, and `( ... ) || fail` turns `set -e` off inside it. Test 532 checks this.
- Each test runs under a 600s wall-clock guard that reports a wedge as 124. A longer test raises it with a `# TEST_TIMEOUT_AT_LEAST: N` line at column 0 within its first 40 lines. It calls `skip_if_out_of_budget` so a slow host skips. The value only raises the budget, and nothing can disarm the guard.
- Run teardown with errexit off: `trap 'set +e; cleanup' EXIT`. Under `set -e` a failing cleanup command becomes the test's exit status (#773). Keep the other signals on their own `trap` line, or errexit stays off for the rest of the run. The guard resets `$?`, so save it first if teardown reads it.
- Never pipe into `grep -q`. It exits on the first match, so the producer takes SIGPIPE on its next `write()` (one per line in bash). `pipefail` makes that the pipeline's status. Then `cmd | grep -q M && fail` never fires, and `cmd | grep -q M || fail` fails on a present marker. Capture the reply, assert its status line because an empty, truncated or redirected reply is marker-free too, then run `grep -q M <<<"$reply"`. `head -c N` and `head -n N` end the same way, and their failure is platform-specific: `tail | head -c 3` exits 141 on the uutils coreutils leg but not on GNU. Use `od -An -c -j <skip> -N <len> file` instead. Test 585 checks the `printf` and `echo` producers.
- Never assert a fault by signal *number*, because SIGBUS is 7 on x86, arm, powerpc and s390x but 10 on hppa, alpha, mips and sparc. Map it with `kill -l "$n"`.
- A fixture that needs a host to stay silent must settle (500ms), re-probe every socket, and SKIP when one answered. The powerpc and ppc64 buildds refuse TEST-NET-1 right after `connect()`, where runners drop it. `tools/hostile-net.sh` runs a command on such a network.

## Hard invariants
- **Generated autotools files are NOT in git.** `configure`, every `Makefile.in`, `config.h.in`, `ltmain.sh`, `config.guess/sub` and the aux scripts are `.gitignore`d, regenerated by `./bootstrap`, and shipped only in `make dist` tarballs. After editing `configure.ac`, a `Makefile.am` or `m4/`, re-run `./bootstrap` and reconfigure before testing, then commit only those sources.
- **Format only changed lines** with `git clang-format` (clang-format 19), because the engine was formatted by an old tool and won't round-trip.
- **Edit the binary `fuzz/corpus/*` vectors byte-wise** (`perl -0pi`, `sed`), never through a UTF-8 re-encoder. The rest of the tree, `lang/*.txt` and `html/contact.html` included, is UTF-8.
- **The `Protect master` ruleset requires three checks: `ci gate`, `windows gate` and `DCO sign-off`.** A gate fails unless every job in its workflow passed or skipped on purpose. Add a new job to its gate's `needs:`, which `496_ci-tier2-split.test` checks.
- **A required status context must stay on a workflow that runs on `pull_request`**, or every open PR waits for it forever. So never move a required job to `tier2.yml`, which never runs on a PR. `496_ci-tier2-split.test` fails when a required check stops being emitted.

## Security (HTTrack parses hostile input off the network)
- Bounds-check every copy as `untrusted < limit - controlled`, never `controlled + untrusted < limit`, which can wrap and pass.
- **Abort or clip is a decision, not a default.** The `*_safe_` helpers (`strcpybuff`, `strlcpybuff`, `strcatbuff`) **abort** on overflow, which suits our own data. Data from a cache, a header or the wire would then crash on malformed input, so clip it with `strclipbuff(dst, size, src)`.
- **A warning class is not the unsafe set.** `-Wformat-truncation` fires only on a *bounded* `snprintf` whose return is discarded, never on an unbounded `sprintf`. Before a hardening pass, grep `\bsprintf\s*\(`, `\bstrcpy\s*\(` and `\bstrcat\s*\(` yourself.

## Changing the parser
`src/htsparse.c` rewrites every page of every mirror, but the suite crawls fixtures the parser already handles. A regression there reaches us months later as a forum post. Treat a change here with more care than its diff size suggests.
- **Widening what the parser SCANS is as dangerous as changing what it REWRITES.** #1377 touched only the list of scanned mime types, and so carried a years-old rewrite bug into every ordinary script. #497 widened mid-tag attribute detection, which then rewrote `data-*` values that were never links.
- **Locate your guard in the pipeline before you write it.** A string may already be entity-decoded and truncated at `#` and `?` when it reaches your test, so read what happened to it upstream.
- **Prove it by differential against the previous release binary.** `bash tools/parser-diff.sh` builds both, crawls `tools/parser-corpus/` with each and diffs the mirrors. Until two running binaries confirm it, a source read is a hypothesis. Run `--self-check` first to prove the diff can see a change.
- **Pair every probe with a control that fires.** Include a mutant that wrongly rejects, to show the differential sees a loss and not only a gain.
- **Name the class you mean to change, then prove the class you changed equals it.**

## C conventions
- **Use the `*t` allocator wrappers from `htssafe.h`, never raw libc**: `malloct`/`calloct`/`realloct`/`freet`/`strdupt`, in test and selftest code too. `freet` NULLs its lvalue argument and tolerates NULL, and `calloct(n, sz)` keeps calloc's argument order. The only exception is storing or calling a libc symbol itself, such as a resolver-backend function pointer.
- **Pass an output buffer as `hts_buf`, and a read-only byte range as `hts_span`.** An internal function takes `hts_buf` (`src/htsbuf.h`) for a buffer it writes and `hts_span` (`src/htsurlport.h`) for a (pointer, length) input, never a separate pointer and size. Pass an array as `HTS_BUF(arr)`, so the compiler supplies the size. A span is not NUL-terminated, so use its helpers rather than `strlen` or `str*` calls. Grep both headers for a helper before writing one. Exported `HTSEXT_API` functions keep `(char *, size_t)`, because `htsbuf.h` is not an installed header.
- **Grow an array with `TypedArray(T)` from `src/htsarrays.h`, not a hand-written `realloc`.** `TypedArrayPush` and `TypedArrayReserve` return `HTS_FALSE` and leave the array unchanged when memory runs out, so check the result. `TypedArrayAt` aborts on an index past the end.
- **`tools/check-api-lint.py` fails on three patterns in new C code.** A raw `strcpy`, `strcat`, `strncpy`, `strncat`, `sprintf` or `vsprintf` call must use an `hts_buf` or an `htssafe.h` helper instead. A file-scope or `static` array of pointers must be `*const`, as in `static const char *const names[]`. A function that only its own `.c` file uses must be `static`, not declared in a header.
- **The lint baselines in `tools/api-lint/` can only shrink.** When you fix a listed violation, the lint fails until you delete its entry. Run `tools/check-api-lint.py --update` to regenerate the files. Add an entry only for a case the rule cannot judge, such as a table the code writes, and say why in the PR.
- **Compare names case-insensitively with `hts_streq_ci`, `hts_starts_with_ci` and `hts_skip_prefix_ci` from `src/htsctype.h`.** `""` equals `""` and is a prefix of every string, so guard a non-literal operand that may be empty.
- **Test a status range through its named predicate**, such as `statuscode_is_http`, `statuscode_is_internal`, `back_in_flight`, `back_holds_transfer` or `back_is_live`, never through a bare `> 0` or `>= STATUS_READY`. Give an integer mode a typed enum, and switch over it with no `default:`, so `-Wswitch` reports a missing case.
- **Pass many same-typed arguments as one struct built with designated initializers**, as `parse_fetch_flags` and `warc_record` do. Each call site then names every value.
- **Mark `HTS_CHECK_RESULT` on any function whose result a caller must act on.** `tools/check-api-lint.py` fails on a header function that can return failure without it, and `tools/api-lint/check-result.txt` lists the old cases. To discard a result on purpose, write `(void) !f(...)` with a one-line comment saying why.
- **Hold a monotonic clock reading as `hts_mono` from `src/htsmono.h`, not a bare `TStamp`.** Take it with `hts_mono_now()`, move it with `hts_mono_add_s` or `hts_mono_add_ms`, and compare it with `hts_mono_before` or `hts_timeout_elapsed`. Adding a plain number to a reading does not compile, so seconds, milliseconds and wall-clock stamps cannot mix.
- **Take a minimum or maximum with the typed `hts_min_int`, `hts_max_size`, `hts_min_i64` and their siblings in `src/htsbase.h`.** The `min` and `max` macros are gone because they evaluated an argument twice. The installed `htsglobal.h` keeps `minimum` and `maximum`, but new code does not use them.
- **Join a directory and a file name with `hts_path_join`, or with `hts_fpath_join` for a path handed to the OS.** Both take an `hts_buf` and put one `/` between the parts. Both return `HTS_FALSE` with the buffer emptied when the result does not fit, so check the result rather than use a truncated path.
- **Exported API is `HTSEXT_API`.** Everything else is hidden by `-fvisibility=hidden` and free to change (check with `nm -D --defined-only libhttrack.so`). Changing an installed-header struct (see `DevIncludes_DATA` in `src/Makefile.am`) or an exported signature breaks the ABI. Flag and discuss it, bump the soname, and prefer keeping the old entry point beside a new one.
- **Windows ABI is free to break, POSIX is not.** The Windows DLL ships next to the exe with no soname contract, so a `_WIN32`-only ABI change needs no deprecation.

## Code & prose
- Be terse. Comment the why, in English, and translate French comments you touch.
- Strip AI tells (em-dash overuse, rule-of-three, filler, vague attributions) from all prose, PR text included. See Wikipedia's "Signs of AI writing". Claude Code users run prose through `/humanizer`.
- A behavior change needs a test. Prefer a hidden `httrack -#test=NAME` engine self-test, driven by a `tests/NN_*.test`, over a slow crawl. `-#test` lists them.
- **A self-test lives in `hts<module>_selftest.c`, beside the module it exercises.** Its `selftests_<module>[]` table is declared in `htsselftest_int.h` and walked by `hts_selftest()`. Fixtures that more than one module needs go in `htsselftest_util.c`. A new file must be listed in `src/Makefile.am` and `src/libhttrack.vcxproj` (test 342).
- Queue a list of self-test assertions with `selftest_queue` + `selftest_run_queued`, which run them in one engine. Queued args reach the handler verbatim, so a case testing an argv rewrite keeps `assert_selftest` (CR/LF/TAB to a space, `(none)`, quote stripping, alias expansion). So does a case whose output shell logic reads.

## Review your change adversarially (strongly suggested)
Do this before pushing, and when reviewing others.
- **One invariant at a time.** Name a property the diff must keep (bounds hold, cache/wire format unchanged, no use-after-free, ABI stable), then build inputs that break it.
- **Audit tests against the spec, not the code.** For each new test, try to build a buggy path that still passes it. If one exists, the test is confirmation-biased. Never copy observed output in as the expected value.
- **A green suite does not prove the old behavior was chosen.** `htsdns_selftest.c` asserted the never-re-resolve bug that #1392 fixes, and a purge guard firing on any dead link passed all 372 tests. A fix that inverts an existing assertion makes that inversion the finding.
- **Floor a sweep's count in the `.test`**, because the count depends on the corpus. Use the real count, not a round one, and prove the floor by deleting a case.
- **Risk areas need runtime probes.** A static or unit check is not enough for hostile-input parsing, struct layout/ABI, cache/wire format or a security path. Exercise the wrong behavior at runtime (Claude Code: `/review-recipe`).
- **Poison a canary, never compare it against zero.** A `'\0'` check cannot see the stray NUL of an off-by-one terminator. Fill it with a non-zero byte and kill both the stray-`'X'` and stray-NUL mutants. Neither ASan nor `_FORTIFY_SOURCE` sees an overflow inside the same struct.
- **Overshoot every destination, not one.** Oversizing one field cannot tell a per-field bound from a shared one, or from a fix bounding only that field. Exercise each destination across at least two capacities, and check what the code emits before writing expected values.

## Commits
- **Sign every commit off** with `git commit -s`, because the DCO check rejects a commit without a `Signed-off-by` trailer.
- **An AI-assisted commit carries a `Co-Authored-By:` trailer** naming the assistant, never a PR-body footer.
- PRs are squash-merged, so master keeps one commit per PR, built from its title and description.

## PR descriptions
- The title says what the change does in plain words, not the problem behind it nor the implementation.
- The body is two plain sentences: what it does, and what a reviewer would miss. A third needs a reason. Give what the diff can't show (motivation, tradeoffs, risk), with no What/Why/How template.
- Verify claims against the code and flag drift rather than repeat it. Don't hard-wrap, because GitHub reflows, and add no "Generated with Claude" footer.
